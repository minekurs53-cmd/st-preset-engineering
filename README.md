# st-preset-engineering

[English](README.en.md) | 简体中文

**SillyTavern 预设工程 Skill** —— 对任意 SillyTavern（酒馆 / ST）预设 JSON 做「解剖 → 诊断 → 手术 → 验证 → 交账」的代理技能（Agent Skill）。

> **设计目标一句话**：让一个带内容安全审查的 AI 代理，也能安全地逆向、诊断、维护、重构含有敏感内容的社区预设——把敏感正文挡在它的"上下文与产物"之外，尽量不触发平台拦截与输出截断。

它不是又一份预设编写教程。每条纪律都蒸馏自真实逆向工程项目（数百条目 / 1.5MB / 多脚本 / 多正则的重型预设全流程实践），包括全部踩过的坑——`st-preset-engineering/references/pitfalls.md` 每条教训都附真实案例与结构性防线。

## 功能特性

### 七步骨架（按需进入，不是每次全跑）

```
S0 定红线 → S1 建档案 → S2 拿真值 → S3 做诊断 → S4 开手术 → S5 验证 → S6 交账
```

| 步骤 | 做什么 | 关键纪律 |
|---|---|---|
| S0 | 定红线 | 源只读 + 哈希前后校验；敏感产物三分流；远程依赖默认停用 |
| S1 | 建档案 | 结构档案（孤儿/死槽/分组/正则/脚本）+ 扩展挂点清单 + 复杂度分级 |
| S2 | 拿真值 | mock 捕获 / 离线装配 / 用户真实 dump 三级真值的选择与适用边界 |
| S3 | 做诊断 | 结构/行为/效果三类缺陷；每条结论挂来源标签（实测/结构事实/推定/未验证） |
| S4 | 开手术 | 生成器三断言（唯一性/枚举/等值），**禁止手改大 JSON** |
| S5 | 验证 | 三层验证门从便宜到贵，跨门即停 |
| S6 | 交账 | 改造清单 + 用户手册 + 未验证清单如实标注 |

### 按请求类型路由 + 复杂度自适应

"看看这个预设有什么问题"只走 S0→S1→S3（报告即产物）；"翻个开关"只走 S0→S4(最小)→S5(L1)，分钟级任务不杀鸡用牛刀；重构走全流程。条目数 / 脚本数 / 正则数决定 light / medium / heavy 档位，heavy 预设强制加"脚本 UI 对条目名的引用扫描"。

### 实例参数与骨架分离：换预设家族 = 换 profile

预设家族相关的全部事实（路径 / 红线命令 / 分组记号语义 / 模型分支配对 / 槽位契约 / 复杂度）都存在 `preset-profile.json`，骨架文件跨预设不变。`examples/preset-profile.sample.json` 是一份可直接套用的脱敏模板。

## 安全特色：让"有审查"的代理安全处理敏感预设

### 场景

SillyTavern 社区预设普遍夹带成人向指导与对抗平台审查的指令工程内容。一个带内容安全审查的代理**直接读**这种 JSON 时：敏感正文进入上下文 → 命中平台安全策略 → **拒答、输出截断、任务中断**；而且这些正文还会随诊断报告、git 提交继续扩散。常见做法是"别让代理碰"，于是维护者只能手改 1.5MB 的 JSON——恰好是本 skill 用生成器三断言证明过必错的路。

### 思路：让"会被审查的内容面"保持干净

审查器只能命中**在场**的文本。本 skill 把敏感正文挡在场外：分析工作面落在脱敏后的 PUBLIC 档上（词表命中 0），原文只存在于隔离目录与工具管道里；真正的字节级修改由生成器脚本在**文件层**完成，原文不经过模型上下文。

### 五层措施

1. **占位符化管线（核心）**。词表驱动的脱敏器把敏感正文替换为 `«BLOCK:NNN»` / `«NAME:NNN|类别»` 占位符，**完整保留机器可读骨架**（identifier / prompt_order / 宏与变量名 / XML 标签 / 正则 flags），且可**逐字节还原**（`verify-structure` 验证"改动完全局限于被映射槽位"，`restore` 还原）。代理全程在词表命中 0 的 PUBLIC 档上做结构分析与装配对账。

2. **词表判据，不靠目测**。什么算"敏感"由检测词表的命中数说了算，不是"我觉得没问题"。配套 `explain` 子命令防过严脱敏——实测一个通用词能把 32% 的内容误判为敏感，过严的安全边界会逼人绕路（pitfalls.md 教训 L7）。

3. **敏感产物三分流**。按分析深度选隔离强度：`placeholder-pipeline`（长期分析：PUBLIC 档可外发 + 对照表锁死在 gitignore 目录）/ `quarantine`（副本放 gitignore 目录，产物不出仓库）/ `none`（无敏感内容）。**含敏感正文的产物绝不进 git 历史**；对照表由工具强制锁目录——被拒绝说明放错位置了，改路径而不是绕过工具。

4. **红线前置 + 权限边界声明**。S0 是第一步，任何文件操作之前先立规矩：源预设只读、改动前后跑哈希校验、外发档必须词表命中 0、预设脚本里的远程外链**默认停用**（不替用户决定执行远程代码）、mock 端点仅监听 127.0.0.1。SKILL.md 首屏就有「安全边界声明」，用户在使用前即可了解行为范围。

5. **精瘦上下文**。SKILL.md 约 100 行（硬上限 300），细节全部在 11 篇 references 里按需加载。上下文里没有冗余文本 = 更少的审查暴露面与更小的截断压力。

### 为什么能减少截断（机制，不是承诺）

- **无内容可命中**：主分析面（PUBLIC 档）词表命中 0，审查器没有可匹配的敏感正文 → 没有触发拦截的理由。
- **暴露面最小化**：敏感正文只存在于隔离目录 / 工具管道 / 仓库外，不进上下文摘要、不进报告、不进 git 历史——每一层都有"命中 0"的程序化判据，可以在任务前自证。
- **仓库自证**：本仓库全部文本文件经词表审计，产物面命中 0；不含任何密钥、凭据与真实路径。

### 如实声明（边界）

本 skill **降低**敏感内容进入上下文与产物的暴露面、并给出可复跑的自证命令，但**不承诺"永不截断"**——平台审查策略不受本 skill 控制；`quarantine` 路线下代理仍需在本机读隔离副本（产物不出仓库）。能验证的只有：发布包干净、工作面干净、产物面干净——这三层都有命令可查。

## 安装

```bash
git clone https://github.com/minekurs53-cmd/st-preset-engineering.git
```

- **目录式**（Claude Code 等支持 skills 目录约定的平台）：把 `st-preset-engineering/`（中文版）或 `st-preset-engineering-en/`（英文版）整个目录放进 `~/.agents/skills/`（用户级）或 `<项目>/.agents/skills/`（项目级）。
- **打包式**（claude.ai → Settings → Capabilities → Skills → 上传）：下载 Release 附带的 zip 直接上传，或自行打包 skill 目录。
- **验证安装**：代理应先读 profile（或先建最小 profile），再进入 S0 定红线——如果它跳过红线直接改 JSON，说明加载的不是本 skill。

## 快速上手

1. **准备实例参数**：在工作目录或仓库根建 `preset-profile.json`。冷启动直接抄 `references/profile-spec.md` 的"最小 profile"模板，S0/S1 跑完自动填大半；`examples/preset-profile.sample.json` 是一份填好的脱敏样例。
2. **说一句话触发**，例如：
   - "帮我看看这个预设有什么问题"
   - "把这个预设的字数档改一下"
   - "给这个预设加一个新模型分支"
   - "重构这个预设，把僵尸条目清掉"

## 系统要求与依赖

| 项 | 要求 |
|---|---|
| 代理平台 | 任何支持 Agent Skills 约定（SKILL.md frontmatter + 目录式加载）的平台 |
| skill 本体 | 纯 Markdown，无内置脚本，无外部网络访问 |
| 配套工具带 | 结构档案 / 脱敏管线 / mock 端点 / 离线装配 / 审计 / 引用扫描等步骤工具以**能力契约**约定（toolmap.md 的九张契约卡），Python 3.8+ 标准库即可实现；`profile.tool_dir` 登记本地实现——现成脚本或按契约新建的等价工具均可 |
| 无工具带时 | 不阻塞：S0 哈希校验可用任意 sha256 工具替代；其余按对应契约卡在本地实现（实例数据外置 / 只读写盘纪律 / 输出面最小 / 结论可 diff / 自测先行），自测通过登记进 profile。skill 第 0 步规定：读不到的引用必须明确报告，**不许静默跳过** |

> **工具为什么不打包**：脱敏管线依赖敏感词表（实例数据）。skill 层与工具层解耦是刻意设计——skill 只约定工具的能力契约，实现由本机提供；换预设家族只换 profile，不换骨架。

## 兼容性

- 面向支持 Agent Skills 约定的代理平台（SKILL.md frontmatter + `.agents/skills` 目录或 claude.ai 上传）。
- 处理对象是任意 SillyTavern 预设 JSON；对带脚本面板、条目管理界面、世界书联动的复杂预设（heavy 档）有专门纪律。
- 英文版与中文版骨架完全一致，任选其一安装即可，不必同时安装。

## FAQ

**Q：工具在哪里拿？**
A：本仓库不绑定具体工具——skill 约定的是每类工具的**能力契约**（输入 → 判定逻辑 → 输出格式 → 期望输出，见 `references/toolmap.md` 九张契约卡）。本机有现成实现就登记进 `profile.tool_dir` 直接用；没有就由代理按契约卡在本地实现等价工具（Python 3.8+ 标准库即可，附自测），再登记使用。S0 的哈希校验用任意 sha256 工具即可替代。无论哪种路径，skill 都会明确报告哪条引用失效，不会静默跳过。

**Q：我的预设没有敏感内容？**
A：profile 里 `sensitive_strategy: "none"`，管线照走、跳过脱敏；其余纪律（源只读 / 生成器三断言 / 三层验证）完全不变。

**Q：这个 skill 会不会教代理写对抗内容？**
A：不会。它处理的是预设的**工程结构与维护纪律**；对抗类档位语义默认不登记进 profile（少登记少敏感面），脱敏管线把敏感正文挡在分析面之外，仓库本身经词表审计。

**Q：中文版和英文版有什么区别？**
A：内容一一对应，只有语言不同。触发词方面中文版对中文口语（"酒馆预设""翻个开关"）覆盖更自然，英文版适合英文工作流；按自己的使用习惯选一个装。

**Q：能给不同的预设家族用吗？**
A：这正是 `preset-profile.json` 的设计目的——换预设家族 = 换 profile，骨架不动。陌生分组记号体系下，skill 会把分组判读降级为参考并当面问用户，**不猜测**（实测：不同记号体系的预设会产生分组假阳性，已写进 pitfalls）。
