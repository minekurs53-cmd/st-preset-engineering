# ST 预设工程

对 SillyTavern 预设 JSON 做 **解剖 → 诊断 → 手术 → 验证 → 交账**。本 skill 的每条纪律都蒸馏自真实逆向工程项目的实战教训（`references/pitfalls.md`，每条都真实发生过），不是通用最佳实践的泛泛罗列。

## 安全边界声明（使用前必读）

- **文件访问**：只读写 profile 登记的路径（工作副本、仓库外产出目录）；源预设目录**只读**，任何操作前后跑 `profile.verify_command` 校验
- **网络**：不访问任何外部服务；mock 端点仅监听 127.0.0.1；预设脚本里的远程外链默认停用（`references/red-lines.md` 规则 7），不替用户决定执行远程代码
- **不做的事**：分析面默认落在词表命中 0 的 PUBLIC 档上（占位符管线，见 `references/red-lines.md` 规则 2）；不手改大 JSON（必走生成器三断言）；敏感产物不进任何版本库
- **无密钥**：本 skill 不含、不请求任何 API 密钥或凭据

## 第 0 步：读 profile（永远第一个动作）

预设的实例参数（路径/红线/分组语义/分支配对/复杂度）存在 `preset-profile.json`：

1. 查找顺序：当前工作目录 → 仓库根 → `~/.preset-profiles/<预设名>.json`
2. 找不到 → 先按 `references/profile-spec.md` 建最小 profile（跑完 S0/S1 就能填大半），再继续
3. profile 里每条路径/命令都必须实际可跑；**读不到的引用要明确报告，不许静默跳过**（骨架期工具未建，`verify_command`/`tool_dir` 允许先占位，建成自测后立即回填）
4. **冷启动四问**（用户在场时开工前问齐，异步任务不问、按括号内默认走并在交付中声明）：
   - 本机有无酒馆可做 B1 捕获？有无真实对话/dump？（默认：无→行为类全进未验证清单）
   - 本次只要诊断，还是后续要手术/重构？（默认：按当前请求的最小路由建工具）
   - 产物只自用、要外发还是要入库？（默认：quarantine 防过度，外发先化名）
   - 实际在用的模型渠道？（默认：按预设出厂分支诊断）

## 步骤路由（按需进入，勿全跑）

| 用户请求类型 | 走哪几步 | 说明 |
|---|---|---|
| "这个预设怎么样/有什么问题" | S0→S1→S3 | 报告即产物，不动手 |
| 翻开关 / 换路线 / 改采样参数 | S0→S4(最小)→S5(L1) | 分钟级任务，别杀鸡用牛刀 |
| 改条目正文 / 加删条目 | S0→S1(档案过期才重跑)→S4→S5(L1+L2) | |
| 加模型分支 | S0→S1→S3→S4→S5(L1+L2+L3) | 先读 `references/surgery.md` |
| 重构 / 大清理 | 全流程；S4→S5 可多轮，**每轮结束回 S2 重新拿真值** | |
| 效果评估 | S0→S2 | L4 属于用户，不自评（见纪律 2） |

## 七步骨架（每步详解在对应 reference）

```
S0 定红线 → S1 建档案 → S2 拿真值 → S3 做诊断 → S4 开手术 → S5 验证 → S6 交账
```

- **S0**（`references/red-lines.md`）：源只读 + 改动前后校验；敏感产物三分流（脱敏管线 / 仓库外隔离 / 禁分发）
- **S1**（`references/autopsy.md`）：p1 结构档案 + 扩展挂点清单 + 复杂度分级
- **S2**（`references/truth-sources.md`）：B1 mock / B2 离线 / 用户真实 dump 的选择与适用边界
- **S3**（`references/diagnosis.md`）：结构/行为/效果三类缺陷 + 来源标签四分
- **S4**（`references/surgery.md`）：生成器三断言；**禁止手改 JSON**
- **S5**（`references/verification.md`）：三层验证门从便宜到贵，跨门即停
- **S6**（`references/handover.md`）：改造清单 + 用户手册 + 状态同步

## 三条不可违反的纪律

1. **源只读**：一切修改发生在副本上；改动前后跑只读校验（命令在 `profile.verify_command`，没有就先建）
2. **真实数据 > mock > 子智能体扮演**：效果结论只能来自前两者；无法验证就写「未验证 + 缺什么」，**不许用降级措辞把"没验过"说成"通过"**
3. **手术必走生成器三断言**：唯一性（`count==1`）/ 枚举（diff 恰为变更清单）/ 等值（除枚举外逐字节一致）。1MB 的 JSON 手改必错

## 复杂度自适应（骨架不增减，只调深度）

S1 档案产出 `profile.complexity`：

- **light**（≤50 条目、脚本 ≤2、正则 ≤6）：S2 可只用 B2 离线近似
- **medium**：标准流程
- **heavy**（脚本面板多 / 扩展配置块多 / 条目管理 UI）：S3 必须加"脚本交互与挂点耦合"诊断；**改任何条目前先扫脚本对该条目名/组号的引用**——带 UI 的脚本常按名字索引条目

## 反跑偏自查（每个任务开头 + 每 30 分钟）

1. 这个动作会让用户在酒馆里少遇到什么**具体**问题？答不上来就停（教训：文档自激励）
2. 我是不是在给自己的产物做验证/写文档？（教训：自己验自己）
3. 有没有更便宜的真实实验？mock 一小时 > 写一场文档
4. 重心在"用户能用上"还是在"流程严谨"？重心漂移要靠用户拉回过两次——别等第三次

## 工具层（先看有没有，没有就按契约建）

`profile.tool_dir` 指向的工具目录可能是现成的，也可能不存在——不存在不阻塞流程。九个步骤工具的能力契约（输入 → 判定逻辑 → 输出格式 → 期望输出）与**建工具方法论**（实例数据外置 / 只读写盘纪律 / 输出面最小 / 结论可 diff / 自测先行）都在 `references/toolmap.md`：工具在跑就照卡调用；不可跑就按对应契约卡在本地实现等价工具（Python 3.8+ 标准库即可），自测通过后登记进 profile 再继续。新建工具在交付说明中逐个声明。

## 在受治理仓库内工作的叠加义务

若本次工作发生在带会话收尾义务的仓库（以该仓库自己的 AGENTS.md / 协作文档为准）：收尾时叠加其收尾约定——状态同步 + 验证套件复跑 + 提交，并把新发现的错误登记进该仓库的勘误通道。

**豁免与冲突**：只读类任务（路由表里"报告即产物，不动手"的）不触发仓库写义务；若会话存在外部硬约束（如测试守则、用户明令禁止写仓库），**以硬约束为准**，跳过的收尾义务在交付中逐条声明——不许静默跳过，也不许为守规矩而破约束。
