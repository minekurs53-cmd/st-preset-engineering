# best-practices.md — 写正文/改模板前的实践清单

> **何时读**：写新条目正文、改输出模板、设计开关结构前。
> **来源**：成熟预设逆向 + 社区教程（旅程 wiki《拼好预设》、官方文档、负向指令研究）+ 实测校准。每条都经过真实运行检验。

## 结构与顺序

1. **U 型注意力**：身份/框架放头，格式要求/输出模板/尾部输入压尾，资料居中，聊天记录靠底——首尾权重最高（位置偏差研究的共识 + 社区实测一致）。**新增约束确认它经吐出点落在尾部区**。
2. **生效层唯一**：开关状态只认 `prompt_order[].order[].enabled`；给"条目身上的 enabled"做的任何假设都会错（失真快照）。
3. **组号三铁律**：永不重排旧号；新组取"全局最大号+1"；跨阶段不复用同号——老用户"照旧勾选"才不会指向别的功能。**补充（易错点）**：给现有互斥族加新成员（如为新模型加分支）时**加入现有组**，不另取新号——拆出独立组会让"双 ON 误配"从 L1 可查退化为静默。
4. **配对靠共享槽**：分支与模板的绑定写进变量槽读写关系并登记进 profile，**不靠名字配对**；建档时核对"模板读的槽 == 本路线写的槽"。
5. **孤儿归零**：每加一条必入 order；每删一条连 order 一起删；不许"留在 prompts[] 当备件"。

## 指令写法

6. **正向为主，禁令保底**：展示"要遵循的模式"比堆"不要 Y"有效（粉红大象效应）；每条禁令**成对给正向替代**（"禁 X → 改写为 Y"）。
7. **禁令可自查化**：把"禁止 X"写成模型能执行的检查动作（"每写完一段自查本段 X 为零"）+ 能被外部程序断言的词表。
8. **字数用模块锚定**：纯数值区间实测同向漂移 ~12%；"每模块约 N 字 × M 模块 + 写前分配 + 写后自查"实测有效。**档位条目内直接写好当档的分配数**，别让模型做除法。
9. **封闭枚举**：让模型"从这几类里选"而不是"种类要多样"——开放措辞诱发自创种类（实测偏差）。
10. **强调要省着用**：加粗/‼️/威胁式措辞只放在最高价值约束上；处处强调=没有重点。
11. **示例克制**：内嵌示例必须少而多样 + 显式"禁止照抄本示例句式"——否则风格退化为固定腔。

## 输出模板 / 思维链

12. **标签单一字面**：全预设一个思维链标签名（含变体、对冲写法都算矛盾）；同一请求里两个标签名=模型在错误位置输出思维链。
13. **标签是契约**：模板标签 ↔ 美化/去除正则 ↔ 压缩正则的字面量逐字耦合——改任何一侧前全库扫消费方（改摘要标签实测=整楼消息清空消失）。
14. **思维链载体按模型选型**：reasoning 通道模型（API 返回 reasoning_content）正文不再要求输出标签；标签型渠道才用正文模板 + 字面强制。混用=双重思维链。
15. **伪预填充要写续写规则**：请求以 assistant 闭标记收尾时，模板需显式"从结束标记直接续写正文，不得重开思维链"——否则实测会重开思维链、标签失衡。
16. **role 即行为**：同族条目 role 一致（user×N/system×1/assistant×1 是真实分布）；新条目 role 照抄同族，不按感觉设。

## 参数与元数据

17. **连接字段不进预设**：`custom_prompt_post_processing` 等 isConnection 字段写进 JSON 不生效——写进交付说明让用户 UI 核对。**若深度 SOP 与本清单冲突，以本清单+源码取证为准**，并把冲突登记进勘误通道。
18. **机读元数据**：顶层补 name/version/changelog——版本只写在"必读"正文里=用户关掉即消失。
19. **抗性按模型配**：作者实证的抗性组合逐模型登记（resistance_pack）；默认态收敛为"至少一个主力模型的合法配置"，不做四不像默认。
20. **模型自报计数不可靠**：靠模型维护的计数器（每 N 次刷新/每 M 倍触发）会漂移——触发条件改绑模型已在稳定维护的信号（如它每轮必写的计数标记），或改由脚本按楼层客观计数。
