# diagnosis.md — S3 做诊断

> **何时读**：S3。
> **产出**：风险清单/诊断报告——每条缺陷 = 描述 + 证据（文件:行号 或 命令输出 或 dump 名）+ 来源标签 + 建议修复路径。**诊断不动手**。

## 三类缺陷（验证路径不同，别混）

| 类 | 例子 | 谁能确认 |
|---|---|---|
| **结构类** | 孤儿条目、死槽、配对断裂（模板读的槽≠本路线写的槽）、标签矛盾（同请求两种标签名）、双 False 正则、互斥组 ON≠1、远程依赖、僵尸 setvar 地雷 | S1 档案即可确认（结构事实） |
| **行为类** | 字数超区间、格式漂移、禁令失效、触发条件不触发、计数漂移 | 需要输出数据（真实模型 > mock） |
| **效果类** | 写得好不好、像不像、用户满意吗 | **只有用户**（L4） |

## 来源标签四分（每条结论必须挂一个）

| 标签 | 含义 | 证据要求 |
|---|---|---|
| **实测** | 真实运行得到 | dump 文件名 / 命令输出片段 / 轮次数据 |
| **结构事实** | 静态结构可证 | `文件:行号` 或可复跑命令 |
| **推定** | 有依据但未验证 | 显式写"推定=…，待实测替换" |
| **未验证** | 缺条件 | **必须写缺什么**（缺 API/缺酒馆/缺 N 轮/需用户提供），不许降级措辞过桥 |

## 诊断流程

1. 从 S1 档案过五项结构风险（孤儿/死槽/双 False/互斥/远程依赖）——全部是**必查项**，不是抽查。远程依赖按 red-lines 规则 8 分级（I/W/E）。**先确认输入类型**：顶层无 `prompts` 键 / `entries` 为 dict（世界书 lorebook 特征）→ 本路由不适用，输出"输入识别 + 降级说明"报告，**不许当"空预设"诊断**（实测：世界书输入被卡 5 输出空报告 exit 0，差点误读）。
2. 配对完整性：每个模型分支，模板 getvar 的槽 == 本路线 ❗1 setvar 的槽？（实测教训：三条路线自洽、一条断裂，无任何报错，只表现为输出降级）
3. 契约扫描（三方一致，工具契约=卡 5 §5 + 卡 9）：条目正文里的标签/格式字面量 ↔ 正则 pattern ↔ 脚本引用，三方一致？**正则侧注意**：字面量提取只认 `</?tag>` 形状，藏在正则语法模式（find 里的 `think` 而非 `<think>`）的消费方会假阴性——字面量矩阵为"单方"的标签要再做一次定向子串核查补证。**alternation 形标签**（`<(a|b|c)>`）`</?tag>` 形提取直接漏检 → 矩阵"单方"实为两方的同款坑，由同一"定向子串核查"兜底（实测 `<(thinking|suggestions|disclaimer)>` 被判单方、实际两方）。
4. 行为类缺陷：拿 S2 真值对照模板要求逐项量（字数/格式/触发/计数），**每项给数字**（达标率、出现次数、漂移事件数）。**无真值时的默认出路**（B1/B2 都不可达：无本机酒馆、quarantine 策略不产 PUBLIC 档）：行为类全部进"未验证清单"并**逐条写缺什么**（缺 dump/缺 N 轮/缺哪条路径），不许写"通过"也不许静默省略——诊断报告的完成判据=五项必查对账表 + 未验证清单，两者齐才算完成。
5. 汇总：按 error（会不可逆损害/静默失效）→ warn（系统性偏差）→ info（改进机会）排序；每条写"修复方向"（不是修复本身——修复进 S4）。

## 报告格式（最小模板）

```markdown
## 诊断：<预设名>（基线：<开关态声明>）
### Error
- [E1] <缺陷> — 结构事实（<命令/文件:行号>）→ 修复方向：<…>
### Warning
- [W1] <缺陷> — 实测（<dump/数据>，<数字>）→ 修复方向：<…>
### Info
- [I1] <改进机会> — 推定（<依据>）
### 扩展挂点清单
- <S1 产出的挂点三问结论落此节（block / kind / status / note 表格）>
### 未验证清单
- <事项> — 缺<什么>
```

## 跨预设共享基建（同一作者/姊妹预设互拷的识别）

同一预设家族或姊妹预设会互拷基建（同名条目 + 同 inj_order、正则族互拷、同族悬浮窗脚本）——这类跨预设关系不登记，单份报告会漏掉"它其实是某姊妹预设系列的一部分"这类上下文（实测：两个预设共享同名条目（同 inj_order、同参数）、正则族互拷、同族悬浮窗，跨预设报告互引可定位）。多预设同场诊断时：

- 同名条目（同 inj_order/同状态）跨预设出现 → 在各自报告的 Info 登记"跨预设共享基建"并互引；
- 同族正则/脚本互拷 → 标注来源预设与需同步面；
- 跨预设判定仍只列结构事实，不猜作者意图。

## 纪律

- 诊断结论**全部进唯一勘误通道**（若仓库有）；不在多个文档各说各话。
- "作者为什么这么写"的意图问题，如实标"不可判"——判能用的只有结构与行为，不判心。
- 发现文档/前场结论错了 → 登记勘误（编号接续），**不悄悄改写历史结论**。
