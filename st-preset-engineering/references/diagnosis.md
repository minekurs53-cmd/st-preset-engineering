# diagnosis.md — S3 做诊断

> **何时读**：S3。
> **产出**：风险清单/诊断报告——每条缺陷 = 描述 + 证据（文件:行号 或 命令输出 或 dump 名）+ 来源标签 + 建议修复路径。**诊断不动手**。

## 三类缺陷（验证路径不同，别混）

| 类 | 例子 | 谁能确认 |
|---|---|---|
| **结构类** | 孤儿条目、死槽、配对断裂（模板读的槽≠本路线写的槽）、标签矛盾（同请求两种标签名）、双 False 正则、互斥组 ON≠1、远程依赖、僵尸 setvar 地雷 | S1 档案即可确认（结构事实） |
| **行为类** | 字数超区间、格式漂移、禁令失效、触发条件不触发、计数漂移 | 需要输出数据（真实模型 > mock） |
| **效果类** | 写得好不好、像不像、用户满意吗 | **只有用户**（L4） |

## 来源标签四分（每条结论必须挂一个）

| 标签 | 含义 | 证据要求 |
|---|---|---|
| **实测** | 真实运行得到 | dump 文件名 / 命令输出片段 / 轮次数据 |
| **结构事实** | 静态结构可证 | `文件:行号` 或可复跑命令 |
| **推定** | 有依据但未验证 | 显式写"推定=…，待实测替换" |
| **未验证** | 缺条件 | **必须写缺什么**（缺 API/缺酒馆/缺 N 轮/需用户提供），不许降级措辞过桥 |

## 诊断流程

1. 从 S1 档案过五项结构风险（孤儿/死槽/双 False/互斥/远程依赖）——全部是**必查项**，不是抽查。
2. 配对完整性：每个模型分支，模板 getvar 的槽 == 本路线 ❗1 setvar 的槽？（实测教训：三条路线自洽、一条断裂，无任何报错，只表现为输出降级）
3. 契约扫描：条目正文里的标签/格式字面量 ↔ 正则 pattern ↔ 脚本引用，三方一致？
4. 行为类缺陷：拿 S2 真值对照模板要求逐项量（字数/格式/触发/计数），**每项给数字**（达标率、出现次数、漂移事件数）。
5. 汇总：按 error（会不可逆损害/静默失效）→ warn（系统性偏差）→ info（改进机会）排序；每条写"修复方向"（不是修复本身——修复进 S4）。

## 报告格式（最小模板）

```markdown
## 诊断：<预设名>（基线：<开关态声明>）
### Error
- [E1] <缺陷> — 结构事实（<命令/文件:行号>）→ 修复方向：<…>
### Warning
- [W1] <缺陷> — 实测（<dump/数据>，<数字>）→ 修复方向：<…>
### Info
- [I1] <改进机会> — 推定（<依据>）
### 未验证清单
- <事项> — 缺<什么>
```

## 纪律

- 诊断结论**全部进唯一勘误通道**（若仓库有）；不在多个文档各说各话。
- "作者为什么这么写"的意图问题，如实标"不可判"——判能用的只有结构与行为，不判心。
- 发现文档/前场结论错了 → 登记勘误（编号接续），**不悄悄改写历史结论**。
