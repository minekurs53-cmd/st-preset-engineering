# red-lines.md — S0 定红线

> **何时读**：S0；任何涉及敏感内容或外发的操作前。
> **为什么 S0 是第一步**：13 场实战中，唯一可能造成不可逆损害的不是技术错误，而是越线（源被改、敏感内容入库）。S0 的全部成本是几条命令，全部收益是把"不可逆"挡在门外。

## 规则 1：源只读 + 前后校验

- 源文件/源目录**一字不改**。所有修改发生在工作副本上。
- 有哈希基线的（profile.hash_baseline 或 manifest 工具）：**任何操作前后各跑一次** `profile.verify_command`，期望 `[verify] OK`；无基线的先算 sha256 记入 profile。
- 校验失败 → 停下，先查是谁改的，**不要继续任何手术**。

## 规则 2：敏感内容三分流

先判定预设是否含敏感内容（NSFW 指导/破甲指令/受限词）。判定工具是词表扫描（`04_audit_for_git.py` 或脱敏器 `scan`），**不要靠目测**——实测证明目测会漏（一个通用词能把 32% 内容误判，见 toolmap 的 explain 卡）。

| 策略 | 适用 | 做法 |
|---|---|---|
| `placeholder-pipeline` | 含敏感正文且要长期分析/修改 | 脱敏管线产 PUBLIC 档（词表命中 0，可外发）+ 隔离档；对照表只进 gitignore 目录 |
| `quarantine` | 含敏感但无需正文级分析 | 工作副本放 gitignore 目录，直接在副本上改，产物不出仓库 |
| `none` | 词表命中 0 | 可正常入库 |

- **含敏感正文的产物绝不进 git 历史**（进了历史就难清除）。
- 引用敏感条目名时用化名（`«NAME:NNN|类别»`）或占位符（`«BLOCK:NNN»`），**不要手抄原名进任何会入库的文档**。
- 工具会强制这条（脱敏器拒绝把含原文对照表写到敏感目录外）——被拒绝说明你放错地方了，**改路径而不是绕过工具**。

## 规则 3：外发判定

- 外发（贴给他人/上传/发帖）只用满足 `outbound_files_pattern` 的档；判据是**词表命中 0**，不是"我觉得没敏感"。
- 导出件（含完整正文的可导入 JSON）一律仓库外；入库的是文档、工具、PUBLIC 档。

## 规则 4：写盘纪律

- 一切工具写文件显式 `newline="\n"`——Windows 文本模式曾让"逐字节还原"差 4896 字节。
- 生成器写 JSON 用 `ensure_ascii=False, indent=4`，写完即算 sha256 记入产出说明。

## 规则 5：正则双 False 禁令（error 级）

- `markdownOnly=false` 且 `promptOnly=false` 且未禁用的正则会**永久改写聊天记录**（实测落盘实锤：消息本体与 swipe 的标记被剥除不可逆）。
- S1 档案发现这类正则 → 诊断报告列为 **error**，修复方式 = 拆成显示侧（markdownOnly）+ 提示词侧（promptOnly）两条，或经用户同意后禁用。**不许留着**。

## 规则 6：连接字段不过预设（源码级教训）

`custom_prompt_post_processing` 等连接绑定字段**写进预设不生效**（ST 源码：预设切换时跳过 isConnection 字段）。需要特定值时：写进交付说明让用户在 UI 手动核对，**不要写进预设 JSON 假装已生效**（media_inlining 这类 `isConnection=false` 字段才随预设走）。

## 规则 7： 远程依赖默认停用

脚本里 `injectScript`/外链 JS 的（不可验证域名）：S1 登记为风险；默认 `enabled=false` 并在交付说明写明恢复方法。别替用户决定执行远程代码。

## S0 收尾检查（30 秒）

- [ ] 只读校验通过（前、后各一次）
- [ ] 敏感策略已定且产物位置符合分流表
- [ ] 待入库文件词表命中 0
- [ ] 没有任何生成物写进了源目录
