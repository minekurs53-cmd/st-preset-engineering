# truth-sources.md — S2 拿真值

> **何时读**：S2；任何要下"效果"结论前。
> **为什么不可省**：本 skill 的第一条纪律就是"真实数据 > mock > 子智能体扮演"。没有真值的"验证"是自己验自己——本项目为此浪费过三场会话。

## 真值路径决策表

| 我要回答的问题 | 用哪条路径 | 理由 |
|---|---|---|
| 这次修改后装配出的请求变了吗？变了哪几条消息？ | **B2 离线装配**（改前改后各跑一次，逐消息 diff） | 便宜、可重复；结论必须标"离线近似" |
| 酒馆真正组装出的请求长什么样？ | **B1 mock 捕获** | 请求侧真值；需本地酒馆 |
| 模型实际看到什么、实际输出什么？ | **用户真实请求 dump / 真实对话** | 唯一完全真值；向用户要 |
| 效果好不好？修复有没有用？ | **L4：用户真实模型实测** | 永远不自评 |

## B1 mock 捕获（请求侧真值）

```bash
python <tool_dir>/p2_mock_llm.py --port 9999
```
酒馆侧：API 连接 → Chat 补全来源 → Custom (OpenAI-compatible) → `http://127.0.0.1:9999/v1` + 任意 key + 模型名任意 → 连接 → 选预设 → 发一条消息 → 读 dump（**落仓库外临时目录**）。

- 能证明：条目装配、开关生效、定位语位置、模板唯一性、宏展开——**装配层**。
- 不能证明：模型行为、效果、**用户脚本层的改写**（见下）。
- 纪律：用临时聊天、正则/脚本钩子按提示选否、用后设置复原副本删除——零残留。

## B2 离线装配（近似）

```bash
python <tool_dir>/p5_agent_eval.py assemble --config default --pub <PUBLIC档> --tag <名字> --out-dir <仓库外目录>
```
- 输入必须是 PUBLIC 档（词表命中 0）——红线。
- **每次输出都标注"离线近似"**；它复刻装配语义但由工具实现，与酒馆真值的差异要心里有数（消息合并、运行时增补、连接字段处理）。

## 用户真实数据（最高价值）

- **十轮真实对话 > 一万字分析**。向用户要的形态：聊天导出 jsonl / 请求响应 dump / 三个具体指标。
- ⚠️ **脚本层遮蔽**：带工具脚本的预设，用户实跑时请求历史可能已被改写（实测案例：前几轮被压成摘要、开场白移除、伪 user 消息注入）。所以：
  - B1 只证明**装配层**，不等于"模型看到的"；
  - 对账"模型实际看到什么"，以用户**实际请求 dump** 为准；
  - S3 诊断时把"脚本层改写"列为独立变量，别把它误记成预设行为。

## 思维链通道警告（断言适用边界）

- 有的模型思维链走正文标签（`<thinking>…</thinking>`），有的走 API 协议级 `reasoning_content`（正文 0 标签）。
- **标签字面断言只适用于"标签型"渠道**；对 reasoning 通道模型，正文里查标签=永远查不到（实测十轮 0 次出现），不代表模型没思考。
- 判断渠道：看响应里有没有 `reasoning_content` / ST 的 `reasoning_type`。

## L4 交给用户的标准姿势

工作流以**交付测试协议**收尾，而不是自评：
1. 基线声明（哪套开关态、哪个文件、sha 前 16 位）
2. 玩法（同类剧本 N 轮）
3. **3~5 个可数指标**（例：正文达标率、某模块触发率、违禁记号数/轮——各带对照基线值）
4. 明说："结果发我，我回填档案/矩阵"
