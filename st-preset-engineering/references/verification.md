# verification.md — S5 验证（三层门，从便宜到贵）

> **何时读**：S5；写"验证通过"三个字之前。
> **纪律**：门从便宜到贵排列，**跨门即停**——L1 挂了不进 L2；每道门回答不同的问题，互相不可替代。
> **无工具时**：每道门引用的工具跑不了，就按 toolmap 对应契约卡自建（L1=卡 5，L2=卡 7，L3=卡 8），自测通过再验证——**不许跳过验证门，也不许用目测代替**。
> **无环境 ≠ 无工具**：工具可自建，环境不可自建——L3/B1 需本机酒馆，L2/B2 需 PUBLIC 档（quarantine 策略不产）。环境缺条件时：该门结论如实标"未验证 + 缺什么"，**不许降级措辞过桥**，也不许用低层门"全绿"暗示高层门通过。

## L1 结构层（分钟级，必走）

```bash
python <tool_dir>/p1_evidence.py report --preset <产物.json>
```

| 判据 | 期望 | 违反说明 |
|---|---|---|
| 孤儿条目 | 0（或与改动前一致且逐条有理由） | 条目没接进 order=白写/幽灵引用 |
| order 悬空引用（stale refs） | 0（或与改动前一致且逐条有理由） | order 引用不存在的 identifier＝旧版残留/命名断裂，热升级改名的常见事故 |
| 死槽（只写不读） | 0（新增死槽=本次引入的债） | 有人写了永远没人读的变量 |
| 互斥组 ON 数 | 每组恰 1（设计使然的例外要在档案登记） | 配置违反/双模板 |
| 分支配对 | 模板 getvar 槽 == 本路线写入槽 | 配对断裂=静默降级 |
| 双 False 正则 | 0 | 永久改写聊天记录（error） |
| 绝对注入 / sp=true 标注 | 与改动前一致且逐条有理由 | 改顺序对它们无效——漏登记=对注入形态的改动会假绿 |

⚠️ **L1 盲区（实测发现）**：L1 全绿 ≠ 语义一致。写死在其他 ON 条目正文里的档位数值/字数下限（如换字数档后，思考档条目仍写"正文不足一千二百字"禁止）**能通过全部组规则检查**——换档类/联动类改动必须加做：全库 ON 条目正文扫描（数字锚点）或 L3 装配真值人工核对。

## L2 装配层（改前改后对账）

```bash
python <tool_dir>/p5_agent_eval.py assemble --config default --pub <改前PUBLIC> --tag before --out-dir <目录>
python <tool_dir>/p5_agent_eval.py assemble --config default --pub <改后PUBLIC> --tag after  --out-dir <目录>
```

- **判据：归一化占位符后，逐消息 diff == 恰好预期变更集合**。多一条=意外改动；少一条=漏改。
- 噪声处理先校准（教训：占位符编号会因条目增删移位——`«BLOCK:NNN»`→`«BLOCK:X»` 归一化后再比）。
- 结论标注"**离线近似**"。`p5 check` 断言器只适用**标签型思维链**渠道；reasoning 通道模型的输出不进正文标签，别用它打分。

## L3 mock 真值（涉开关/条目/参数结构变更时必走）

- B1 捕获改后预设的装配请求（见 truth-sources.md）。
- 判据：装配形态与设计一致（模板唯一、定位语位置、宏展开干净、无泄漏）。
- 限度照说：只证明装配层；用户脚本层可能再改写——那句结论写给用户时要带这句。

## L4 效果层（永远属于用户）

- 交付**测试协议**：基线声明（开关态+文件+sha16）→ 同类剧本 N 轮 → 3~5 个可数指标（各带对照基线值）→ "结果发我，回填档案"。
- **禁止**：子智能体扮演模型、假想模型、自写断言器给自己的产物打分。
- 没跑 L4 的交付物，效果结论一栏写"**未验证——缺 N 轮真实实跑**"，这不是缺陷声明，是诚实。

## "验证通过"三个字的门槛

同时满足才许写：L1 全绿 + L2 diff==预期 + （涉结构变更时）L3 形态正确 + 效果结论如实标"未验证"或引用了用户实测数据。**三层混用一次=报告作废重写**。
