# autopsy.md — S1 建档案（解剖）

> **何时读**：S1；遇到陌生结构/扩展块时。
> **产出**：结构档案（p1 报告）+ 扩展挂点清单 + 复杂度分级 → 回填 profile.structure / complexity。
> **核心原则**：解剖结论必须可复跑（命令或探针脚本），**不靠目测读 1MB JSON**。
> **无工具时**：跑不了契约卡 5 就按 toolmap 的建工具方法论自建结构档案工具（六节报告就是输出契约），自测通过后再跑——**不许跳过档案直接目测**。

## 1. 跑结构档案

```bash
python <tool_dir>/p1_evidence.py report --preset <预设.json>   # 任意预设（契约卡 5）
python <tool_dir>/p1_evidence.py report --target <已登记版本>  # 已登记的源版本 ⛔（版本名单是实例数据）
python <tool_dir>/p1_evidence.py drift                          # 跨版本漂移（有多版本时）
```

报告怎么读（每节对应一类风险）：

| 节 | 内容 | 看什么 |
|---|---|---|
| §1 管道表 | 每条目：开关态/阶段/分组/角色/字数/变量操作 | **启用列才是生效态**（prompts[].enabled 是失真残留，别用它）；role 分布是否与族语义一致（assistant=伪预填充载体）；**绝对注入条目**（injection_position=1，不随内联顺序、按 depth 注入聊天记录）与**自定义 sp=true 条目**要单独列出——改它们顺序不影响注入点（均有实测） |
| §2 槽位表 | setvar/addvar 写入者 vs getvar 读取者 | **只写不读=死槽**（原版 7 个，全是历史尸体）；同一槽多个 setvar 写入者=时序地雷（停用条目被启用会清空主槽——僵尸条目检查）；**"读"的判定范围=条目正文+脚本+正则三处**（世界书/角色卡不在范围，声明即可）；NO_STATIC_WRITER（三处写者计数 0）=推定运行时写入（手动 /setvar 或外部注入），待用户确认 |
| §3 分组表 | 记号×阶段 → 成员与 ON 数 | **互斥组 ON≠1 = 配置违反**；但先确认记号语义（见 §3 已知限度）；**单成员组不算组语义**（多为装饰性前缀，标"命名约定"降噪） |
| §4 孤儿表 | 在 prompts[] 不在 order | 孤儿=功能不存在（不可见/不可开关）；功能性孤儿与垃圾孤儿分开列；**数据容器型条目**（字符数异常大、内容为序列化 JSON，如 `SPreset配置`=extensions 拷贝）单列并标"不应接回"；**反向对账**：order 中引用不在 prompts[] 的 identifier（悬空引用/stale refs）同样单列——热升级改名/换版的典型残留（实测：两张 order 块各挂 2 条旧版 identifier，现行条目反成孤儿） |
| §5 正则表 | 14+ 条的 flags | **双 False 且未禁用 = error**（永久改写聊天记录）；pattern 字面量记入契约清单 |
| §6 脚本表 | 脚本/远程 URL | 外链脚本=风险；脚本名/按钮名单记入挂点清单 |
| 顶层参数 | temperature/max_tokens/media_inlining 等 | **连接绑定字段写进预设不生效**（cpp 教训）——这类参数写进交付说明而非 JSON |

## 2. 扩展挂点清单（复杂预设的核心动作）

对 `extensions` 下每个子块登记一个挂点，逐挂点回答三问：**谁读它？谁写它？改它影响什么？**

```jsonc
// 挂点登记格式（进 profile.structure.extension_hookpoints）
[
  {"block": "regex_scripts", "kind": "ST原生正则", "status": "effective",   // effective|dormant|unknown
   "note": "正则生效层，唯一必改处"},
  {"block": "tavern_helper.scripts", "kind": "酒馆助手脚本", "status": "effective",
   "note": "2 个脚本含悬浮窗 UI；按条目名/组号索引条目 → 改条目前必须扫引用"},
  {"block": "SPreset", "kind": "扩展绑定层", "status": "dormant",
   "note": "同名单正则的第二份拷贝；未装 SPreset 时完全惰性——改正则时两份同步或删绑定层"}
]
```

**三份拷贝定律**：同一数据（如同名单正则）出现多处时，先运行时判定哪份生效（无扩展环境下绑定层惰性），**只改生效层，其余同步或删除，绝不并行维护**。对账走卡 5 §5 的拷贝层对账行（仅原生/仅拷贝层/同名差异），不许人眼比对。

**UI 脚本耦合**：带面板/按钮的脚本常按**条目名或组号字符串**索引条目——S4 改名/删条目前，先对脚本内容做全库引用扫描（把条目名当字面量搜脚本正文）。

## 3. 复杂度分级（驱动流程深度）

| 级 | 判据（满足其一即升档） | 流程影响 |
|---|---|---|
| light | ≤50 条目、脚本 ≤2、正则 ≤6 | S2 可只用 B2 离线近似 |
| medium | 默认 | 标准流程 |
| heavy | 脚本面板/UI、扩展配置块 ≥2、条目 >200、正则 >20 | S3 加"脚本交互与挂点耦合"诊断；S4 前必须做 UI 引用扫描；S5 增加脚本层回归 |

判据与实质不符时（如"扩展块 ≥2 但无脚本无 UI"被判 heavy），按字面判，`complexity.note` 注记实质档位——判据宁可失真也不许自由降档。

## 4. 已知限度（如实声明，不许假装通用）

- **分区/分组识别必须样式无关**：真实样式至少六种——〈…〉标题条目、成对边界条目（——X开始——/——X结束——）、同名成对边界（toggle 型：——X—— 起止同名、二次出现=关闭）、emoji+分类名前缀、HTML 标签成对条目（`<background>…</background>`）、"----X"连字符标题。**同一 skill 会遇到互不兼容的分区家族**：工具内置样式识别不可信，profile 的 `zone_title_re`/`zone_pair_start_re`/`zone_pair_end_re`/`zone_category_re` 数据化规则**优先于内置**；profile 没写且识别不出 → 换探针定向抽取，别在错误识别上盖楼。（实测六种形态全齐（第六种=同名成对，本轮补入）：〈〉/——成对/同名成对/HTML 对/emoji 前缀/━━ 分隔标题；其中 emoji 前缀与 ━━ 分隔两类需要 `zone_category_re` 与"捕获组 1=区名"语义——见 profile-spec。）
- **多拷贝"生效层判定 + 同步核验"要工具化，不手工比对**：同一数据（如正则组）可能有多层拷贝（原生层 + SPreset.RegexBinding + 容器条目 JSON），多层时先判哪层生效（无扩展环境绑定层惰性），**只改生效层，其余同步或删**；各层一致性与生效层判定要落可复跑命令或 diff，不许靠"人眼逐字节"（实测：三拷贝逐字节一致 / 两层一致 / 绑定层为空——三种形态都要能自证）。
- **规则（选一/互斥）证据的三种形态**，都合法，都要查：
  1. 标题条目聚类（图例/说明条目写明记号语义）
  2. 成员名内嵌标注（条目名含"(选一)/(选1)/互斥"等——实测一个预设 47 条命中，漏查=漏簇）
  3. 槽表交叉（同槽多写入者 × 上述两形态 → 规则候选集）
  三路证据取交集后登记 `block_rules`；只有一路证据时判"推定"，标待用户确认。
- **图例检索三形态**：图例可能在必读/说明条目正文里（敏感条目不可整读，用探针按行抽）、可能内嵌在条目名（emoji+分类名）、可能压根没有（全靠名内标注+槽表推定）。没有说明条目 ≠ 无规则。
- **emoji 锚点不稳定**：社区预设条目名里的 emoji 带变体选择器，跨脚本匹配常失败。**一切程序化定位用数字/ASCII 子串**（如 "1600-2500"），不用 emoji 全名。
- **多 order 块**：prompt_order 可含多个 character_id 块（历史遗留/分群），逐块登记；生效块通常是最大块/含 dummyId 100001 的块（推定，写来源标签）；只改目标块。
- **identifier 三类形态**（审计前先分类，是引用扫描假阳性的根因）：
  1. **UUID**——自定义条目，稳定可作引用锚点
  2. **ST 内置槽名**（'main'/'nsfw'/'jailbreak'/'scenario'/'charPersonality'/'personaDescription'/'worldInfoBefore'…，完整清单查本机 ST 源码 PromptManager 的内置 identifier 表）——有运行时填充语义，被改名/占用后仍受 ST 填充（推定），不得当普通短词处理；工具内置清单缺项会把这些槽误标"自定义 sp=true"（实测：personaDescription 一度漏收）
  3. **自定义短词**（'nsfw'/'SPresetSettings' 等）——引用扫描时默认高假阳性（见 toolmap 卡 9）
- **探针输出纪律**：自写探针只打印数字/结构/化名，**不打敏感正文**——探针脚本本身可能进 git。

## 5. 引用扫描（S3 前置 / heavy 档 S4 前必跑）

UI 脚本按条目名/组号索引条目（§2 的耦合问题），反向检查靠引用扫描——工具契约见 toolmap 卡 9。要点：

- 消费方三类：脚本正文、正则 pattern/replaceString、条目正文。
- **假阳性判据**：命中须能解释为对该条目的**消费语义**；排除语言关键字/CSS 数值/正则反向引用（`$N`）/标准槽词/脚本自身标识符。短名（纯数字/≤2 字符）与内置槽名命中默认不可信，逐条核实后才算数。
- 实测教训：跳过这步，改名/删除会静默断掉脚本面板的功能；无脚本预设此扫描输出为空（空场景也验证了链路）。
